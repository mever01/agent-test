# Python и типизация

- Минимальная версия — Python 3.12. Новый код должен работать в
  контейнере на 3.12. Используй `list[T]`, `dict[K, V]`, `T | None`
  и типы из `collections.abc` для интерфейсов коллекций.
  Для новых псевдонимов и параметров типов используй синтаксис 3.12:
  `type Alias = ...`, `def parse[T](...)`, `class Consumer[T]`.
  Примеры есть в `app/external_api_clients/schemas.py` и
  `core/broker/consumer.py`.
- Аннотируй аргументы и возвращаемые значения новых функций и методов,
  включая `-> None`. Сохраняй конкретные типы предметной области,
  например `UUID` для идентификаторов и timezone-aware `datetime`
  в UTC для временных меток событий.
- Структурированные аргументы и результаты передавай через именованные
  типы. Сначала проверь существующие схемы. Для валидации на границе
  API, очереди или инструмента используй Pydantic v2 (`BaseModel`,
  `model_validate`, `model_validate_json`, `model_dump`). Примеры —
  `DocIngestEvent` и `CreateDraftArgs`. Для внутренних DTO без
  валидации подходит `dataclass`, как `MailMessage`.
- Для LangGraph и словарных форматов внешних SDK используй
  `TypedDict` с известными ключами, как `AgentState`, `AgentUpdate`
  и `ChatMessage`. Нетипизированные JSON-объекты разбирай и проверяй
  на границе интеграции. Запрещено вводить `dict[str, Any]` как
  контракт между прикладными функциями. Для простых отображений с
  произвольными ключами и единообразными значениями подходит
  `dict[K, V]`. Одиночные параметры передавай как скаляры.
- Максимум 88 символов на строку нового и изменяемого Python-кода.
  Переноси импорты, вызовы и сигнатуры в скобках, по одному элементу
  на строку с завершающей запятой. Длинные сообщения разбивай на
  соседние литералы с сохранением пробелов и переводов строк.
  Если формат внешних данных требует неделимой строки, держи
  исключение локальным. Избегай массового форматирования старого кода.
- Группируй импорты в порядке стандартная библиотека, сторонние пакеты,
  локальные `app` и `core`. Предпочитай абсолютные импорты.
  Следуй принятым именам `snake_case`, `PascalCase`, `UPPER_CASE`.
- При рефакторинге обновляй имена переменных и аргументов вместе с типами.
  Объекты DAO называй `dao`, `document_dao`, `email_dao`, а не `repo`
  или `repository`. Обновляй также тесты, команды запуска и документацию.
- Сохраняй асинхронный I/O в API, воркере, клиентах и DAO.
  Выноси блокирующие операции из event loop, например через
  `asyncio.to_thread`, где это уместно.
